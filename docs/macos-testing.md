# macOS 验证清单

此清单用于在 Mac 上确认实际行为。Rust 交叉编译和 GitHub Actions 的编译、自检
不能代替桌面端代理和界面的实机验证。分别记录 macOS 版本、CPU 架构、
桌面端版本、Codex CLI 版本和使用的安装方式。

## 构建与安装

- 在 Apple Silicon 和 Intel 构建机分别运行 `bash build-macos.sh <target>`。
- 确认 Rust 测试、Swift 原生组件自检、签名校验和 ZIP 打包通过。
- 解压 ZIP，将 `.app` 放入 Applications，通过 Finder 打开，确认原生组件能够运行。
- 确认使用支持相应 CPU 架构及系统版本的桌面应用；启动器支持 Intel 不代表所有桌面端版本都支持 Intel。

## 启动和代理

- 完全退出桌面端。使用 `--settings` 保存实际代理地址，确认配置文件正确保存。
- 检查本机代理客户端的连接记录，确认桌面端网络请求实际经过指定代理。
- 在桌面端已运行时再次打开启动器，确认提示先退出，没有结束用户进程。
- 使用 `--proxy=...` 覆盖地址，确认桌面端和额度服务使用该代理，配置文件没有被覆盖。
- 使用 `--no-proxy`，确认没有继承终端中的 HTTP_PROXY、HTTPS_PROXY、ALL_PROXY。
- 如果桌面端忽略代理参数或环境变量，记录其版本和具体未代理的功能，
  不应把“启动成功”当作代理验证通过；进一步适配后再发布正式支持声明。
- 设置窗口取消后，确认未保存配置，也未启动桌面端。
- 两个应用同时安装时，确认优先启动 Codex；通过 STARTCHATGPT_APP_PATH 指定其他安装位置。

## 额度和生命周期

- 安装并登录 Codex CLI，桌面端和 CLI 使用同一个账户。
- 分别验证 Homebrew、npm 和自定义 STARTCHATGPT_CODEX_EXE 安装位置。
- 在 Finder 启动环境中测试 npm CLI，确认能够找到其 Node 解释器。
- 仅安装桌面端、不另装 CLI，且不设置 STARTCHATGPT_CODEX_EXE；在 Finder 的精简 PATH 下确认可以发现桌面端内置 CLI 并读取额度。覆盖 `Contents/Resources/codex` 和 `Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex` 两种布局。
- 确认菜单栏和详情窗口显示两个额度周期、正确百分比、本地时区的重置时间。
- 手动刷新、等待自动刷新，确认数据正常更新；额度请求不创建模型任务。
- 临时断开代理，确认旧数字保留、显示过期及错误；恢复后确认自动恢复。
- 重复启动 `--usage-only`，确认不会出现多个菜单栏图标。
- 完全退出桌面端，确认正常启动模式下的额度显示和 CLI 子进程退出。
- `--usage-only` 模式下退出桌面端，确认额度显示继续运行。
- 没有安装桌面端时，用已登录的独立 CLI 打开 `--usage-only`，确认仍能显示额度。
- 打开 `--usage-widget`，确认小窗显示、刷新、关闭和重新打开正常。
- 点击“退出额度显示”，确认桌面端仍在运行，额度服务子进程最终退出。

## 界面

- 测试浅色、深色、Retina 显示和不同菜单栏布局。
- 核对充足、低于 25%、低于 10%、未知和过期状态的颜色与文字。
- 核对两周期都返回重置时间时的详情排版，以及错误文字没有被裁切。
- 缺少桌面端、CLI、原生组件或指定错误路径时，应有明确提示。
